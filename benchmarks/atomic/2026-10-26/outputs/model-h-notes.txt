Model H implementation notes (results pending)

132 payload resources: 21 issues and 111 notes, including 30 embedded comments and 273 embedded checklist items. 20 custom properties + 2 shared classes; built-in Name used as title. Five containers: drive, two account folders, two tables. All nesting is native Value::Json, which creates recursive Loro containers; no complete raw record copy is stored in Model H.

Source timestamps become native millisecond Timestamp columns. Their fixed UTC source spelling is reconstructed losslessly. Null issue closed_at is encoded by absence of that optional typed property; decode restores JSON null for this known nullable field. Other nulls remain native JSON null. Canonical field set and deterministic record ordering come from the fixture schema/IDs. Each reconstructed value is compared to the complete generated fixture, including JSON types and array order.

Initial wire payload comes from the pinned engine handle_sync_vv_reconcile and goes through authenticated loopback WebSocket, native import_sync_push and signed-envelope verification. Sender responses are prepared before the timer, as in the pinned upstream syncd_bulk_benchmark example. Receiver starts open and persistent; startup and challenge authentication are excluded. Empty table queries are registered before timing so normal replication maintains their membership indexes.

The final native import_sync_push call flushes the projection, search/index writes and retained envelopes before returning. Its redb flush makes a nonempty Immediate transaction, committing prior Durability::None writes. This is an OS/filesystem durability boundary, with no simulated power-loss claim. Default periodic flush remains enabled. The API has no callback between final projection visibility and that flush: earlier readable time is unobservable, and separately measured full readability confirmation occurs after durable return.

Incremental receiver stays subscribed on the authenticated socket. Source applies a normal signed save; native DbEvent delta is encoded as UPDATE using the pinned peer live-sync fanout pattern. Receiver validates established source-owner write rights, resolves/merges and persists through native ws_apply. Readable timing confirms the changed field; durable timing adds an explicit Db::flush. Full fixture verification and reopen follow outside both timers. Initial and incremental durability APIs are documented separately.

Received bytes count binary application protocol payload, including frame tags, metadata, snapshots/updates and retained signed envelopes in initial SYNC_PUSH. Challenge/AUTH/HELLO/SUB setup, requests, WebSocket frame overhead, TCP/IP overhead and retransmissions are excluded. No WebSocket compression is negotiated. Loro's internal snapshot/update encoding/compression is included as transmitted. Transport-level compressed or packet bytes are not instrumented.

Disk sizes use summed file lengths (apparent) and st_blocks * 512 (allocated) for each receiver-owned directory, after flush/close and documented reopen. Baseline and total are always retained alongside net growth. Built-in resources, metadata, retained envelopes, Loro oplog history/snapshots, materialized resources, reference/full-text/query indexes and logs are included. Binaries/build/dependency caches and raw result files are excluded. Source/service data storage is reported separately. No compaction is performed.

Other requested Atomic models R/C/O/G remain unmeasured under the later Model H-only priority. Their cells must not be treated as unsupported-engine findings. This run makes no claim about collection-sized resources, recursive projection counts, large-integer precision beyond fixture values, or browser persistence.
