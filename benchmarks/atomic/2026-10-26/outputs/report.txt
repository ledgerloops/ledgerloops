METHOD AND LIMITATIONS
The sender is fully prepared, with native binary engine responses cached before
timing. Fresh persistent receivers are already open; TCP/WebSocket challenge
and owner authentication finish before the SYNC request timer starts. Native
import_sync_push runs with trust_owned=false. Table queries are registered on
the empty receiver so normal import maintains their indexes during timing.
The native LAST import returns after Db::flush, a nonempty redb Immediate
transaction that persists preceding Durability::None writes. Default periodic
flush remains enabled. This is an OS/filesystem boundary, not a power-loss test.
Live UPDATE uses normal DbEvent deltas, checked owner write rights and native
ws_apply resolution/persistence; its durable metric adds an explicit Db::flush.

SCOPE
R, C, O and G are deferred under the later Model H-only instruction, not marked
unsupported. H preserves per-record native rows/links/ACL granularity; its nested
JSON fields have no separate resource identities. R would retain record units
with fewer typed columns. C would trade native per-record rows/links/ACLs for
two structured collection documents. O would replace whole opaque collection
strings. G would use recursive resources; no synthetic count is assumed. None
of those alternatives was measured here. Earlier initial readability is the
specific unmeasured API limitation. Incremental audit-envelope convergence is
also outside this native live-delta test.
