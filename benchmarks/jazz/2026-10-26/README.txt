Synthetic Jazz sync benchmark for https://github.com/ledgerloops/ledgerloops/issues/45

This adapter pins Jazz's relational generation, jazz-tools/jazz-napi 2.0.0-alpha.59.
The registry latest tag (classic 0.20.19) is a different architecture. Classic
CoMap/CoList symbols in this version throw JAZZ_CLASSIC_API_REMOVED. This benchmark
does not measure classic Jazz. The containers model uses ordinary relational rows
for JSON containers; it is not a CoValue implementation.

Run from this directory, on the shared laptop:

  python3 locked.py python3 stage-final.py

This regenerates and verifies the fixture, installs the exact npm lockfile in
/private/tmp, verifies/downloads Chromium Headless Shell build 1194 (version
141.0.7390.37), extracts it using macOS unzip, and runs all six variants. See
browser-artifact.json for the immutable archive URL and SHA-256. This setup is
for the measured macOS ARM64 host. Results are written under
/private/tmp/sync-benchmark-jazz-20261026-runtime/harness/results/<run-name>.
Use a fresh JAZZ_RUN_NAME on every run. Source snapshots are captured per run.

The wrapper acquires the shared lock with atomic mkdir, records task/PID/token,
yields while the originating chat's Atomic priority marker exists, waits at most
30 minutes, and removes only its own lock. For a standalone host change LOCK in
locked.py and the matching guard in run.mjs to a host-local shared lock location.
Do not bypass this wrapper on the six-worker laptop.

Defaults: three warmups, ten measured fresh persistent receivers for each of
native/browser x embedded/containers/collections. Override only for debugging:

  python3 locked.py env JAZZ_RUN_NAME=smoke JAZZ_WARMUPS=0 JAZZ_REPETITIONS=1 JAZZ_RUNTIMES=native JAZZ_MODELS=embedded node run.mjs

Browser installation under Documents stalled after download completion. Runtime
stores and browser binaries therefore default to the isolated path
/private/tmp/sync-benchmark-jazz-20261026-runtime. JAZZ_DATA_ROOT and
JAZZ_BROWSER_ROOT override stores and installed browsers; results record the
actual storage path. Source and user-facing aggregate results remain here.
The final run also staged dependencies outside Documents after a process sample
showed Node blocked synchronously reading jazz-napi/package.json. Earlier startup
failures are excluded from timings; final browser assets are explicit local URLs.

All source fixture records and IDs, JSON nulls and array order are preserved.
Jazz-generated UUIDs are separate from original source IDs. No example.invalid
URLs are fetched. Every account and all data stores are generated by this task.
No personal account, database, browser profile, credential or vendor service is used.

Models:
  embedded: 21 issue + 111 note rows. title/body are string columns; remaining
    fields are embedded in a JSON column. Top-level fields are not discarded.
  containers: every object/array is a separately addressed relational row with
    a JSON-pointer path, scalar JSON and child paths. Arrays retain positions.
    Containers have their own engine row identity and ordinary row authorization
    and replication. Child paths are application-managed links, not magic
    collaborative containers or engine foreign-key constraints.
  collections: exactly two rows, with whole issues and notes arrays as JSON.
    Incremental changes replace that collection's JSON column through db.update.
    The engine remains free to encode/transmit shared chunks internally.

Transport and timing:
  An ordinary synthetic local-first user seeds the local Core server and waits
  for global write confirmation. No backend policy bypass is used for data.
  Sender, Core, schema deploy and fixture import are prepared outside the timer.
  Each initialized-empty receiver is closed for a baseline, then reopened.
  An empty ready-table remote query confirms transport/auth before the timer.
  Time begins immediately before subscribing to every dataset table. Complete
  reconstructed-content equality determines observable completion. Decoding and
  hashing are included; process startup/preparation and reopen verification are not.

  Native durable_ms is a conservative completion upper bound through awaited
  session.close, including subscription teardown and transport shutdown. The
  actual pinned NAPI binary uses RocksDB WalNoSync; its storage.close performs
  flush_wal(true). It is not a dedicated incoming-replication receipt. Do not
  mistake current docs' SQLite description for the measured binary.

  Browser durable_ms is null. graceful_close_upper_bound_ms includes awaited
  Jazz session close and Chromium context close. The published IndexedDB page
  store explicitly requests relaxed transaction durability. Successful reopen
  demonstrates persisted content but does not demonstrate power-loss durability.
  No durability/integrity settings or engine internals are changed.
  Native Node-user initial-sync cadence is not explicitly configured by this
  release's session adapter (core cadence None); RocksDB syncs every 64 backend
  write batches and at close. Browser initialSyncFlushEvery defaults to 512.

  On all receivers, the proxy blocks upstream before reopen; then a local-only
  read must reconstruct the complete fixture. No network repair can hide loss.
  Initial timings and storage precede the incremental mutations. Ten sequential
  title/body pairs run on the final reopened, connected, subscribed receiver.
  Each field gets a unique suffix for its repetition, and the expected fixture
  accumulates both changes. Every operation changes exactly one source field.
  Raw results include minimal contiguous inserted/removed byte counts and full
  API patch sizes. Incremental durable_ms
  is null because there is no separate incoming-update durability receipt.
  Browser incremental timings include the Playwright result IPC overhead. The
  final edited fixture is also verified after an upstream-blocked reopen.

  Exploratory reset failure: initial debugging restored the exact original
  strings after each pair. For two collection JSON rows, restoring the note
  body did not converge within 120 seconds, despite global sender confirmation;
  receiver hash remained the note-body-only edit (6a2abd9a715a96ce7895f778127bc5496
  43937ccb1430336253843358ec881d2). Raw diagnostic results are retained separately.
  The final sequential edit protocol avoids that additional reset operation;
  it does not claim the reset problem was fixed.

Wire accounting:
  A transparent TCP proxy forwards the engine's actual WebSocket replication.
  received_ws_payload_bytes sums all received frame payloads, including protocol
  metadata; received_tcp_stream_bytes also includes WebSocket frame headers.
  These exclude TCP/IP headers, ACKs and retransmission overhead. HTTP/auth/
  negotiation are excluded from the main interval by resetting after ready.
  compressed_ws_frames records WebSocket RSV1 only. Jazz additionally compresses
  channel payloads inside wire-v3 envelopes. The proxy parses the pinned postcard
  envelope to count its declared decoded lengths, compressed payload lengths,
  and codec flags separately. It does not decompress, modify or replay payloads.
  engine_frame_parse_errors must be zero for decoded-channel totals to be used.
  No TLS on the ordinary local ws link.
  Total overhead includes normal identity, permission, version and integrity
  metadata; cryptographic costs are not isolated by disabling checks.
  Local-first authentication signs JWTs with EdDSA/Ed25519 and validates issuer,
  app audience and the claimed identity. Authentication/preparation are outside
  the main timer. Default wire version/session/feature and integrity checks stay
  enabled; no Classic CoValue E2E encryption is implied for this relational API.

Storage:
  Apparent file length and st_blocks*512 allocated bytes are counted recursively
  after receiver close. Native data/accounts, history, indexes, logs and manifests
  are all included. Browser totals include only Default/IndexedDB, Default/Local
  Storage and Default/WebStorage in the dedicated synthetic profile. Executables,
  node_modules, browser binaries/cache and the rest of the profile are excluded.
  Initialized-empty baseline, post-initial-sync total and net are all reported.
  Background/default engine maintenance is retained; no explicit compaction.
  Required Core service and sender storage are separate final post-close totals,
  after all transfers and incremental tests, including synthetic account registry.

Known limits:
  Local loopback on a shared laptop, not WAN performance. Shared lock serializes
  sustained heavy work but does not control OS/user activity, cache warmth or
  thermal state. Cross-engine rankings require matched adapters and durability.
  n=10; p95 uses nearest-rank and therefore equals the largest measured value.
  Node and browser results must not be pooled. Browser cold startup is excluded.
  Native close timings include more than minimum persistence latency. No power
  interruption test is performed. No optional encryption layer is added.
